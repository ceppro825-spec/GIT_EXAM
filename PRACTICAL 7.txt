https://github.com/KalyanM45/Spam-Email-Detection

------------------------------------------------------------

GIT-EXAM

cannot publish changes to the original repository
without write permission.

IMPORTANT:
Branch creation locally and permission to push to
the original GitHub repository are different things.

------------------------------------------------------------
12. REVIEW AND RESOLVE CONFLICTS
------------------------------------------------------------

A merge conflict occurs when Git cannot automatically
combine changes made to the same part of a file.

If a conflict occurs:

STEP 1:
Open the conflicted file in your editor.

STEP 2:
Find the conflict markers.

<<<<<<< HEAD
First version
=======
Second version
>>>>>>> branch-name

STEP 3:
Choose the correct content.

STEP 4:
Remove all conflict markers.

STEP 5:
Save the file.

STEP 6:
Return to GitHub Desktop.

STEP 7:
Stage the resolved changes.

STEP 8:
Enter commit message:

Resolved merge conflict

STEP 9:
Commit the changes.

STEP 10:
Click Push origin.

The Pull Request will be updated automatically.

------------------------------------------------------------
13. INCORPORATE REVIEW FEEDBACK
------------------------------------------------------------

If the reviewer requests changes:

STEP 1:
Read the review comments on GitHub.

STEP 2:
Open the requested file locally.

STEP 3:
Make the necessary changes.

STEP 4:
Save the file.

STEP 5:
Open GitHub Desktop.

STEP 6:
Commit the updated changes.

STEP 7:
Push origin.

The existing Pull Request will automatically
show the new commit.

NOTE:
A conflict or review request may not occur naturally.
Demonstrate the process if required, but do not claim
that a conflict was resolved if none occurred.

------------------------------------------------------------
15. IMPORTANT VIVA QUESTIONS
------------------------------------------------------------

Q1. What is GitHub Desktop?
Ans: A graphical application for performing Git
operations without using terminal commands.

Q2. What is Fork?
Ans: A personal copy of another user's repository.

Q3. What is Clone?
Ans: Downloading a repository to the local computer.

Q4. What is a feature branch?
Ans: A separate branch used to develop a feature
without directly modifying the main branch.

Q5. What is a Pull Request?
Ans: A request to review and merge changes into
another repository or branch.

Q6. Why do we fork a repository?
Ans: To contribute changes when we do not have
direct write access to the original repository.

Q7. What is a merge conflict?
Ans: A situation where Git cannot automatically
combine competing changes.

Q8. What is Commit?
Ans: Saving a snapshot of changes in Git history.

Q9. What is Push?
Ans: Uploading local commits to a remote repository.

Q10. What is the difference between origin and upstream?
Ans: Origin generally refers to your fork, while
upstream refers to the original repository.
