PART 2: PRACTICAL - GITIGNORE
==================================================

AIM:
To create a .gitignore file and demonstrate that Git ignores specified files or folders.

WHAT IS .GITIGNORE?

A .gitignore file tells Git which untracked files and folders should not be tracked or uploaded to GitHub.

STEP 1: OPEN PROJECT DIRECTORY

cd ~/Desktop/GIT_EXAM

STEP 2: CREATE .GITIGNORE FILE

touch .gitignore

STEP 3: OPEN THE FILE

nano .gitignore

STEP 4: WRITE THE FOLLOWING CONTENT

IGNORE/

This rule ignores the entire folder named IGNORE.

Other useful examples:

1.py          Ignore files named 1.py
*.log         Ignore all log files
*.txt         Ignore all text files
__pycache__/  Ignore Python cache folders
.env          Ignore .env file

For this practical, use:

IGNORE/

STEP 5: SAVE THE FILE

In Nano:

Ctrl + O
Press Enter
Ctrl + X

STEP 6: CREATE IGNORE DIRECTORY

mkdir -p IGNORE

STEP 7: CREATE FILES INSIDE IT

touch IGNORE/test1.txt
touch IGNORE/test2.txt

STEP 8: CHECK GIT STATUS

git status

STEP 9: CHECK IGNORED FILES

git status --ignored

EXPECTED OUTPUT:

Ignored files:
    IGNORE/

This confirms that Git is ignoring the folder.

STEP 10: ADD AND COMMIT .GITIGNORE

git add .gitignore

git commit -m "Add gitignore file"

STEP 11: PUSH TO GITHUB

git push

STEP 12: VERIFY ON GITHUB

Open:

https://github.com/ceppro825-spec/GIT_EXAM

The .gitignore file should be visible.

The IGNORE folder and its contents should not appear in the repository.

PART 4: IMPORTANT CONCEPTS
==================================================

1. Does .gitignore delete files from the computer?

No. It only prevents Git from tracking matching untracked files.

2. Why is .gitignore uploaded to GitHub?

Because Git must share the ignore rules with other contributors.

3. Why does an already tracked file still appear on GitHub?

Because .gitignore does not automatically stop tracking files that Git already tracks.

4. How do we stop tracking an already tracked folder?

Command:

git rm -r --cached IGNORE/

Then:

git add .gitignore
git commit -m "Stop tracking ignored folder"
git push

This removes the folder from Git tracking but keeps the local files.

5. Why did git rm --cached give a pathspec error?

Because the IGNORE folder was not tracked by Git. There was nothing to remove.

6. Difference between git add and git commit?

git add stages changes.
git commit saves staged changes in local Git history.
git push uploads commits to GitHub.


PART 5: COMMON ERRORS
==================================================

ERROR 1: Permission denied (403)

Reason:
Terminal is authenticated with an account that does not have write access.

Solution:

gh auth login
gh auth setup-git
gh auth status

Ensure the correct GitHub account is active.

ERROR 2: src refspec does not match any

Reason:
The branch name does not exist locally, or there is no commit to push.

Solution:

git branch
git switch -c GIT-EXAM
git push -u origin GIT-EXAM

ERROR 3: Files are still visible on GitHub

Possible reasons:

1. Wrong folder name in .gitignore.
2. Incorrect .gitignore rule.
3. Files were already tracked before adding the ignore rule.

Check:

cat .gitignore
git status --ignored
git ls-files IGNORE/
