------------------------------------------------------------
1. UNDERSTANDING THE CONCEPTS
------------------------------------------------------------

What is CI/CD?

CI/CD is a software development practice used to automate
building, testing, and deploying applications.

CI means Continuous Integration.

CD means Continuous Delivery or Continuous Deployment.

What is Continuous Integration?

Continuous Integration automatically integrates code changes
and performs build and testing operations.

What is Continuous Delivery?

Continuous Delivery prepares the application for deployment
after successful testing.

What is Continuous Deployment?

Continuous Deployment automatically deploys successful
application changes to the target environment.

What is Jenkins?

Jenkins is an open-source automation server used to create
and execute CI/CD pipelines.

What is a Jenkins Pipeline?

A Jenkins Pipeline defines the sequence of automated steps
required to build, test, and deploy an application.

What is a Jenkinsfile?

A Jenkinsfile is a text file containing the pipeline definition.

What is Docker?

Docker packages applications and dependencies into images
and runs them inside containers.

What is Kubernetes?

Kubernetes manages containerized applications and provides
deployment, scaling, and networking.

What is Minikube?

Minikube provides a local Kubernetes cluster for learning
and practical demonstrations.

6. GIVE JENKINS ACCESS TO DOCKER
------------------------------------------------------------

IMPORTANT:

Jenkins normally runs using a separate Linux user named
jenkins.

We must allow Jenkins to execute Docker commands.

Step 1: Add Jenkins to Docker group.

sudo usermod -aG docker jenkins

Step 2: Restart Jenkins.

sudo systemctl restart jenkins

Step 3: Verify Jenkins service.

sudo systemctl status jenkins

Explanation:

Docker commands are normally restricted to users who have
permission to access the Docker daemon.

Adding Jenkins to the Docker group allows Jenkins to execute
Docker commands.

SECURITY NOTE:

Membership in the Docker group provides powerful access
to the host machine.

7. GIVE JENKINS ACCESS TO MINIKUBE AND KUBECTL
------------------------------------------------------------

This step is important because Jenkins runs as a separate
Linux user.

The Minikube cluster was created using your Ubuntu account.

Jenkins needs access to the same cluster.

Step 1: Copy Minikube configuration to Jenkins home.

sudo cp -a "$HOME/.minikube" /var/lib/jenkins/

Step 2: Give Jenkins ownership of the copied configuration.

sudo chown -R jenkins:jenkins /var/lib/jenkins/.minikube

Step 3: Create a flattened Kubernetes configuration.

kubectl config view --raw --flatten > /tmp/jenkins-kubeconfig

Explanation:

This creates a kubeconfig file containing the required
certificate information.

Step 4: Create Jenkins Kubernetes configuration directory.

sudo install -d -o jenkins -g jenkins -m 700 /var/lib/jenkins/.kube

Step 5: Copy the Kubernetes configuration.

sudo install -o jenkins -g jenkins -m 600 /tmp/jenkins-kubeconfig /var/lib/jenkins/.kube/config

Step 6: Remove temporary configuration.

rm /tmp/jenkins-kubeconfig

Step 7: Verify kubectl is installed.

which kubectl

Step 8: Verify Minikube is installed.

which minikube

IMPORTANT:

Jenkins must have access to:

/var/lib/jenkins/.minikube
/var/lib/jenkins/.kube/config

The Minikube cluster must be running.

This practical uses a local Minikube cluster and is intended
for a laboratory environment.

Do not use this permission arrangement as a production
security configuration.

10. CREATE JENKINSFILE
------------------------------------------------------------

What is Jenkinsfile?

Jenkinsfile is a file that defines the stages of a Jenkins
Pipeline.

We will create three stages:

1. Build
2. Test
3. Deploy

Create the file:

nano Jenkinsfile

Add the following code.

----------------------------------------
FILE: Jenkinsfile
----------------------------------------

pipeline {

    agent any

    environment {

        MINIKUBE_HOME = '/var/lib/jenkins/.minikube'

        KUBECONFIG = '/var/lib/jenkins/.kube/config'

    }

    stages {

        stage('Checkout') {

            steps {

                echo 'Checking out application source code'

                checkout scm

            }

        }


        stage('Build') {

            steps {

                echo 'Building Docker images'

                sh '''
                    docker build -t iris-backend:1.0 ./backend

                    docker build -t iris-frontend:1.0 ./frontend
                '''

            }

        }


        stage('Test') {

            steps {

                echo 'Testing application files'

                sh '''
                    python3 -m py_compile backend/app.py

                    test -f frontend/index.html

                    test -f k8s/deployment.yaml
                '''

            }

        }


        stage('Deploy') {

            steps {

                echo 'Loading Docker images into Minikube'

                sh '''
                    minikube image load iris-backend:1.0

                    minikube image load iris-frontend:1.0
                '''

                echo 'Deploying application to Kubernetes'

                sh '''
                    kubectl apply -f k8s/deployment.yaml

                    kubectl rollout status deployment/db --timeout=180s

                    kubectl rollout status deployment/backend --timeout=180s

                    kubectl rollout status deployment/frontend --timeout=180s
                '''

                echo 'Restarting application deployments'

                sh '''
                    kubectl rollout restart deployment/backend

                    kubectl rollout restart deployment/frontend

                    kubectl rollout status deployment/backend --timeout=180s

                    kubectl rollout status deployment/frontend --timeout=180s
                '''

            }

        }

    }

    post {

        success {

            echo 'CI/CD Pipeline completed successfully!'

        }

        failure {

            echo 'CI/CD Pipeline failed. Check the console output.'

        }

    }

}

----------------------------------------

Save the file.

Press:

CTRL + O
Enter
CTRL + X

11. UNDERSTANDING JENKINSFILE
------------------------------------------------------------

pipeline:

Defines a Jenkins Pipeline.

agent any:

Allows the pipeline to run on any available Jenkins agent.

environment:

Defines environment variables used by the pipeline.

MINIKUBE_HOME:

Specifies the location of the Minikube configuration.

KUBECONFIG:

Specifies the Kubernetes configuration file.

stages:

Contains the different stages of the pipeline.

stage:

Defines an individual stage.

steps:

Contains commands executed in that stage.

sh:

Executes shell commands on the Jenkins agent.

echo:

Displays a message in the Jenkins console.

checkout scm:

Checks out the source code from the configured repository.

post:

Defines actions to perform after pipeline execution.

success:

Executes when the pipeline succeeds.

failure:

Executes when the pipeline fails.

12. UNDERSTANDING THE PIPELINE STAGES
------------------------------------------------------------

STAGE 1: CHECKOUT

Jenkins downloads the application source code from GitHub.

STAGE 2: BUILD

Jenkins builds two Docker images:

iris-backend:1.0
iris-frontend:1.0

STAGE 3: TEST

Jenkins checks:

1. Whether backend Python code compiles.
2. Whether frontend index.html exists.
3. Whether Kubernetes deployment file exists.

STAGE 4: DEPLOY

Jenkins performs the following operations:

1. Loads backend image into Minikube.
2. Loads frontend image into Minikube.
3. Applies Kubernetes deployment configuration.
4. Waits for database, backend, and frontend deployments.
5. Restarts backend and frontend deployments.
6. Verifies rollout status.

The application is now deployed through Jenkins.

21. COMMON ERRORS AND SOLUTIONS
------------------------------------------------------------

ERROR 1: Jenkins cannot execute Docker commands.

Reason:
Jenkins does not have permission to access Docker.

Solution:

sudo usermod -aG docker jenkins

sudo systemctl restart jenkins

Check Docker service:

sudo systemctl status docker


ERROR 2: Permission denied while accessing Docker socket.

Reason:
Jenkins may not have received the updated group membership.

Solution:

Restart Jenkins:

sudo systemctl restart jenkins

Check Docker group:

getent group docker

Verify Jenkins belongs to the Docker group.


ERROR 3: minikube command not found in Jenkins.

Reason:
Minikube is not available in the Jenkins PATH.

Solution:

Check its location:

which minikube

Make sure its installation directory is available
to the Jenkins service.

Common location:

/usr/local/bin/minikube


ERROR 4: kubectl cannot connect to Kubernetes.

Reason:
Jenkins may not have the correct kubeconfig.

Solution:

Check the file:

sudo ls -l /var/lib/jenkins/.kube/config

Verify the Jenkinsfile contains:

KUBECONFIG = '/var/lib/jenkins/.kube/config'

Verify Minikube is running.


ERROR 5: Minikube profile not found.

Reason:
Jenkins cannot access the Minikube configuration.

Solution:

Check:

sudo ls /var/lib/jenkins/.minikube

Verify the Jenkinsfile contains:

MINIKUBE_HOME = '/var/lib/jenkins/.minikube'

Make sure the Minikube profile was copied correctly.


ERROR 6: ImagePullBackOff.

Reason:
Kubernetes cannot find the required Docker image.

Solution:

Check images:

minikube image ls

Load images:

minikube image load iris-backend:1.0

minikube image load iris-frontend:1.0

Verify image names in deployment.yaml.


ERROR 7: Jenkins Pipeline fails during checkout.

Reason:
Repository URL or credentials may be incorrect.

Solution:

Check the GitHub repository URL.

For a private repository, configure Git credentials.


ERROR 8: Jenkins Pipeline fails during Python test.

Reason:
Python code contains a syntax error or Python is unavailable.

Solution:

Check:

python3 --version

Run:

python3 -m py_compile backend/app.py

Correct the syntax error and commit the changes.


ERROR 9: Jenkins Pipeline fails during Kubernetes deployment.

Reason:
The Kubernetes configuration may be incorrect or
the cluster may not be running.

Solution:

Check:

minikube status

kubectl get nodes

kubectl get pods

Check Jenkins Console Output for the exact error.


ERROR 10: New code is not reflected in the application.

Reason:
The image may not have been rebuilt or the deployment
may not have restarted.

Solution:

Check the Build stage.

Check the Deploy stage.

Verify the pipeline runs:

minikube image load iris-backend:1.0

kubectl rollout restart deployment/backend

------------------------------------------------------------

Q1. What is CI/CD?

Ans:
CI/CD is a software development practice used to automate
building, testing, and deploying applications.

Q2. What is Jenkins?

Ans:
Jenkins is an open-source automation server used to create
CI/CD pipelines.

Q3. What is a Jenkins Pipeline?

Ans:
It is a sequence of automated steps used to build,
test, and deploy an application.

Q4. What is Jenkinsfile?

Ans:
Jenkinsfile is a text file containing pipeline instructions.

Q5. What is Continuous Integration?

Ans:
It is the practice of automatically integrating and
testing code changes.

Q6. What is Continuous Deployment?

Ans:
It automatically deploys successful code changes
to the target environment.

Q7. What is the purpose of the Build stage?

Ans:
It creates the Docker images required by the application.

Q8. What is the purpose of the Test stage?

Ans:

validation steps.

Poll SCM periodically checks the source repository

A webhook sends an event notification from GitHub to Jenkins
when a configured event occurs.

Ans:
Poll SCM checks the repository periodically.
A webhook sends a notification when an event occurs.

Q13. What is Docker image building?

Ans:
It is the process of creating a Docker image from a Dockerfile.

Q14. What is Kubernetes deployment?

Ans:
It is the process of running and managing application Pods
using Kubernetes resources.

Q15. What is checkout scm?

Ans:
It checks out the source code from the configured
source code repository.

Q16. What is an agent in Jenkins?

Ans:
An agent is a machine or execution environment where
Jenkins runs pipeline steps.

Q17. What is the purpose of environment in Jenkinsfile?

Ans:
It defines environment variables used by the pipeline.

Q18. What is the purpose of post in Jenkinsfile?

Ans:
It defines actions to perform after pipeline execution.

Q19. What is the purpose of kubectl apply?

Ans:
It creates or updates Kubernetes resources using
configuration files.

Q20. What is the benefit of CI/CD?

Ans:
It reduces manual work, improves consistency, and makes
software delivery faster.
