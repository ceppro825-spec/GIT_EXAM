============================================================

AIM:
To deploy a containerized AI application on a local Kubernetes
cluster using Minikube and perform scaling operations.

------------------------------------------------------------
1. UNDERSTANDING THE CONCEPTS
------------------------------------------------------------

What is Kubernetes?

Kubernetes is an open-source platform used to deploy, manage,
and scale containerized applications.

What is Minikube?

Minikube is a tool that runs a local Kubernetes cluster
on a computer.

What is a Kubernetes cluster?

A cluster is a collection of machines that run containerized
applications.

What is a Pod?

A Pod is the smallest deployable unit in Kubernetes.
It contains one or more containers.

What is a Deployment?

A Deployment manages Pods and ensures the required number
of application replicas are running.

What is a Replica?

A replica is another running copy of an application Pod.

What is a Service?

A Service provides a stable network endpoint to access
a group of Pods.

What is kubectl?

kubectl is the command-line tool used to communicate with
and manage a Kubernetes cluster.

What is a Kubernetes manifest?

A manifest is a YAML file that defines Kubernetes resources.

What is Persistent Volume Claim (PVC)?

A PVC requests storage from Kubernetes so that application
data can persist beyond the lifetime of a container.

6. CONFIGURE DOCKER PERMISSIONS
------------------------------------------------------------

Minikube's Docker driver needs access to Docker.

Check whether Docker works without sudo:

docker ps

If this command gives a permission error, execute:

sudo usermod -aG docker $USER

Then log out of Ubuntu and log in again.

Alternatively, open a new terminal after running:

newgrp docker

Verify:

docker ps

NOTE:

Membership in the Docker group grants powerful access to
the host system, effectively similar to root privileges.

Do not run Minikube with sudo unless specifically required
by your system configuration.

13. CREATE KUBERNETES DEPLOYMENT FILE
------------------------------------------------------------

Enter the k8s directory:

cd k8s

Create the YAML file:

nano deployment.yaml

Add the following configuration.

----------------------------------------
FILE: k8s/deployment.yaml
----------------------------------------

# DATABASE STORAGE
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: postgres-pvc
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 1Gi

---

# DATABASE DEPLOYMENT
apiVersion: apps/v1
kind: Deployment
metadata:
  name: db
spec:
  replicas: 1

  selector:
    matchLabels:
      app: db

  template:
    metadata:
      labels:
        app: db

    spec:
      containers:
        - name: postgres
          image: postgres:16-alpine

          ports:
            - containerPort: 5432

          env:
            - name: POSTGRES_DB
              value: irisdb

            - name: POSTGRES_USER
              value: admin

            - name: POSTGRES_PASSWORD
              value: admin123

          volumeMounts:
            - name: postgres-storage
              mountPath: /var/lib/postgresql/data

          readinessProbe:
            exec:
              command:
                - sh
                - -c
                - pg_isready -U admin -d irisdb
            initialDelaySeconds: 5
            periodSeconds: 5

      volumes:
        - name: postgres-storage
          persistentVolumeClaim:
            claimName: postgres-pvc

---

# DATABASE SERVICE
apiVersion: v1
kind: Service
metadata:
  name: db
spec:
  selector:
    app: db

  ports:
    - port: 5432
      targetPort: 5432

  type: ClusterIP

---

# BACKEND DEPLOYMENT
apiVersion: apps/v1
kind: Deployment
metadata:
  name: backend
spec:
  replicas: 1

  selector:
    matchLabels:
      app: backend

  template:
    metadata:
      labels:
        app: backend

    spec:

      initContainers:
        - name: wait-for-database
          image: postgres:16-alpine

          command:
            - sh
            - -c
            - |
              until pg_isready -h db -p 5432 -U admin -d irisdb;
              do
                echo "Waiting for database..."
                sleep 2
              done

      containers:
        - name: backend
          image: iris-backend:1.0
          imagePullPolicy: IfNotPresent

          ports:
            - containerPort: 5000

          env:
            - name: DB_HOST
              value: db

            - name: DB_NAME
              value: irisdb

            - name: DB_USER
              value: admin

            - name: DB_PASSWORD
              value: admin123

---

# BACKEND SERVICE
apiVersion: v1
kind: Service
metadata:
  name: backend
spec:
  selector:
    app: backend

  ports:
    - port: 5000
      targetPort: 5000

  type: ClusterIP

---

# FRONTEND DEPLOYMENT
apiVersion: apps/v1
kind: Deployment
metadata:
  name: frontend
spec:
  replicas: 1

  selector:
    matchLabels:
      app: frontend

  template:
    metadata:
      labels:
        app: frontend

    spec:
      containers:
        - name: frontend
          image: iris-frontend:1.0
          imagePullPolicy: IfNotPresent

          ports:
            - containerPort: 80

---

# FRONTEND SERVICE
apiVersion: v1
kind: Service
metadata:
  name: iris-frontend
spec:
  selector:
    app: frontend

  ports:
    - port: 80
      targetPort: 80
      nodePort: 30080

  type: NodePort

----------------------------------------

Save the file.

Press:

CTRL + O
Enter

14. UNDERSTANDING THE KUBERNETES YAML FILE
------------------------------------------------------------

apiVersion:

Specifies the Kubernetes API version used by the resource.

kind:

Specifies the resource type.

Examples:

Deployment
Service
PersistentVolumeClaim

metadata:

Contains the resource name and labels.

spec:

Defines the desired configuration of the resource.

replicas:

Specifies the number of application Pods required.

selector:

Identifies the Pods managed by a Deployment or targeted
by a Service.

template:

Defines how Kubernetes should create Pods.

containers:

Defines the containers running inside a Pod.

image:

Specifies the Docker image used by the container.

containerPort:

Specifies the port used inside the container.

env:

Defines environment variables.

volumeMounts:

Mounts persistent storage inside a container.

PersistentVolumeClaim:

Requests persistent storage for PostgreSQL.

Service:

Provides network access to a group of Pods.

ClusterIP:

Provides internal communication within the cluster.

NodePort:

Exposes a service through a port on the Kubernetes node.

initContainers:

Runs a setup task before the main application container starts.

readinessProbe:

Checks whether a container is ready to receive traffic.

imagePullPolicy: IfNotPresent:

Uses the locally available image if it already exists.

20. SCALE THE APPLICATION
------------------------------------------------------------

What is scaling?

Scaling means increasing or decreasing the number of
application instances according to the requirement.

In Kubernetes, we can scale a Deployment by changing
its replica count.

Step 1: Check current backend replicas.

kubectl get deployments

Initially:

backend   1/1

Step 2: Scale backend to three replicas.

kubectl scale deployment backend --replicas=3

Step 3: Check Pods.

kubectl get pods

Expected:

Three backend Pods should be running.

Step 4: Check backend Deployment.

kubectl get deployment backend

Expected:

READY: 3/3

Step 5: Scale down to one replica.

kubectl scale deployment backend --replicas=1

Step 6: Verify.

kubectl get deployment backend

Expected:

READY: 1/1

IMPORTANT:

Scale the backend, not the database.

The database is kept at one replica in this practical because
we have not configured database replication.

The frontend continues accessing backend Pods through
the same backend Service.

27. COMMON ERRORS AND SOLUTIONS
------------------------------------------------------------

ERROR 1: minikube command not found

Reason:
Minikube is not installed or is not available in PATH.

Solution:
Install Minikube and verify:

minikube version


ERROR 2: Docker permission denied

Reason:
Current user cannot access Docker daemon.

Solution:

sudo usermod -aG docker $USER

Log out and log in again.

Verify:

docker ps


ERROR 3: Minikube fails to start

Reason:
Docker may not be running or the computer may not
have enough available resources.

Solution:

sudo systemctl start docker

Check:

docker ps

Try:

minikube start --driver=docker


ERROR 4: ImagePullBackOff

Reason:
Kubernetes cannot find or download the required image.

Solution:

Check images:

minikube image ls

Load the image again:

minikube image load iris-backend:1.0

minikube image load iris-frontend:1.0

Check the image name in the YAML file.


ERROR 5: Pod is in Pending state

Reason:
The Pod may be waiting for storage, resources, or scheduling.

Solution:

kubectl describe pod pod-name

Check the Events section.


ERROR 6: Pod is in CrashLoopBackOff

Reason:
The container repeatedly starts and exits due to an error.

Solution:

kubectl logs pod-name

Check the application code and configuration.


ERROR 7: Backend cannot connect to database

Reason:
Database may not be ready or connection details are incorrect.

Solution:

kubectl get pods

kubectl logs deployment/db

kubectl logs deployment/backend

Verify the DB_HOST environment variable is:

db


ERROR 8: Application is not opening

Reason:
Frontend Service may not be configured correctly.

Solution:

kubectl get services

kubectl get pods

Run:

minikube service iris-frontend --url

Use the URL displayed by the command.


ERROR 9: PVC is Pending

Reason:
Storage provisioner may not be available.

Solution:

kubectl get pvc

kubectl get storageclass

Check Minikube status and storage provisioner.

Minikube may take some time to initialize storage.
